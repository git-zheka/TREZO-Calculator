# Райдер — Next.js

Облік прокату звуку та світла: замовлення, замовники, парк обладнання, окупність кожної одиниці, календар зайнятості.

Next.js 16 (App Router, React 19). Дані — або у JSON-файлі на диску, або в Postgres: обирається однією змінною, решта коду про це не знає.

Покрокова інструкція «від нуля до робочого посилання» — у **[DEPLOY.md](./DEPLOY.md)**. Формули метрик і форма даних — у **[DATA-MODEL.md](./DATA-MODEL.md)**.

---

## Швидкий старт локально

```bash
npm install
cp .env.example .env.local     # заповни APP_PASSWORD і AUTH_SECRET
npm run dev                    # http://localhost:3000
```

Ніякої бази для старту не треба: без `DATABASE_URL` дані лягають у `data/rider.json`, файл створюється сам при першому запуску.

| Змінна | Що це |
|---|---|
| `APP_PASSWORD` | Пароль, яким заходиш у застосунок |
| `AUTH_SECRET` | Випадковий рядок для підпису cookie: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `STORAGE` | `json` або `postgres`. Без неї: є `DATABASE_URL` → postgres, немає → json |
| `DATA_FILE` | Куди класти JSON. Типово `data/rider.json` |
| `DATABASE_URL` | Connection string із Neon, обовʼязково **pooled**. Тільки для режиму postgres |

## Два сховища

`src/lib/db.ts` — тонкий фасад, який вибирає реалізацію: `store-json.ts` або `store-pg.ts`. Обидві експортують один і той самий набір функцій, тож решта застосунку однакова в обох режимах, і перемикання — це одна змінна оточення, а не переписування коду.

**JSON** (`data/rider.json`) — увесь стан одним документом. Запис іде через тимчасовий файл і `rename`, тож обрив не лишає половинчастого JSON; паралельні збереження шикуються в чергу, інакше два одночасні записи затирали б одне одного. Бекап — просто скопіювати файл.

**Postgres** — чотири таблиці, `db/schema.sql`, застосовується через `npm run db:push`.

Коли переїжджати на Postgres: **на Vercel файлова система ефемерна**, запис у файл там або впаде, або зникне при холодному старті. Тобто JSON — для локальної роботи й для хостингу зі справжнім диском; для Vercel потрібен Postgres. Перенести дані з файлу в базу — задача на один скрипт, форма даних однакова.

## Як усе влаштовано

**Читання — серверний компонент.** `app/page.tsx` одним заходом тягне всі чотири таблиці (`loadSnapshot`) і віддає готовий знімок клієнтському `AppShell`. Пагінації немає навмисно: кілька сотень замовлень — це десятки кілобайт, а весь набір на клієнті робить аналітику й календар миттєвими, без жодного запиту при перемиканні вкладок.

**Запис — server actions.** `app/actions.ts`, кожна закінчується `revalidatePath("/")`, тож після збереження сторінка сама перечитує дані. Ніякого SWR, React Query чи клієнтського стану, який треба тримати в синхроні з базою.

**Авторизація — `proxy.ts`.** Один пароль із env, cookie підписана HMAC-SHA-256 через Web Crypto (працює на Edge без бібліотек). Під захистом усе, крім `/login` і ICS-фіду — той має власний секрет у шляху, бо Google Календар не вміє логінитись.

**Календар — підписка, а не синхронізація.** `/api/ics/<token>` віддає живий `.ics`. Google Календар підписується на URL і перечитує його сам; далі броні видно у віджеті Google Календаря на телефоні. Жодного OAuth, жодних токенів у базі, нічого не треба натискати. Секрет у шляху ротується кнопкою в застосунку.

**PWA.** `manifest.ts` + іконки в `public/`. З телефона: Chrome → меню → «Додати на головний екран», далі відкривається як окремий застосунок без адресного рядка.

```
src/
  proxy.ts                 авторизація на кожен запит
  lib/
    types.ts               форма даних
    format.ts              гроші, дати, українські множини
    calc.ts                ВСІ формули: суми, окупність, замовники, сезонність, конфлікти
    db.ts                  фасад: вибір сховища
    store-json.ts          JSON-файл на диску
    store-pg.ts            Postgres через Neon
    auth.ts                підпис cookie
    ics.ts                 генерація календарного фіду
  app/
    page.tsx               серверний компонент: знімок сховища
    actions.ts             server actions на запис
    login/page.tsx
    api/ics/[token]/route.ts
    manifest.ts
  components/
    AppShell.tsx           вкладки, модалки, виклик actions
    OrdersView / CalendarView / GearView / ClientsView / StatsView
    OrderSheet / GearSheet  форми
    BarChart.tsx            графіки на голому SVG, без бібліотек
    RateBlock / IcsPanel
db/schema.sql              схема, ідемпотентна
scripts/db-push.mjs        застосовує схему
scripts/migrate-json-to-pg.mjs  переносить JSON у Postgres
```

`lib/calc.ts` — чисті функції без залежностей від React і бази. Якщо колись схочеш мобільний клієнт або звіт у PDF, уся арифметика вже відокремлена.

## Рішення, які варто знати, перш ніж правити

**Позиції замовлення лежать документом (`jsonb` у Postgres, вкладений масив у JSON), а не окремою таблицею.** Вони незмінні після збереження і ніколи не потрібні окремо від замовлення — нормалізація дала б лише join на кожен рендер. Пошук «де задіяна ця одиниця» покриває gin-індекс.

**Ціна й назва копіюються в позицію на момент створення.** Піднімеш прайс — минулі замовлення й окупність не перепишуться заднім числом. Це не денормалізація за недоглядом, а те, як має поводитись облік.

**Дати ходять рядками `YYYY-MM-DD`.** У SQL вони дістаються через `to_char`, бо драйвер робить із колонки `date` обʼєкт `Date` у зоні процесу, і `toISOString()` на машині за UTC зсуває день назад. Класична пастка, через яку виступ 12-го стає виступом 11-го.

**Гривня й долар не конвертуються ніде,** крім однієї формули окупності, і лише коли курс заданий вручну в налаштуваннях. Без цього техніка, куплена за долари, ніколи не окупилась би гривневими замовленнями.

**У гроші рахуються тільки замовлення зі статусом «Виконано».** Підтверджені й заявки зайняті в календарі та в прогнозі завантаження, але не в доході й не в окупності.

## Що додати далі

- **Відмови окремою сутністю.** Статус `cancelled` є, але заявки, які не дійшли навіть до замовлення, ніде не фіксуються. Саме вони показують спад раніше за дохід.
- **Офлайн-черга.** У підвалі клубу мережі немає. Запис у IndexedDB + відправка при появі звʼязку — service worker уже потрібен для PWA, залишиться додати чергу.
- **Знос обладнання.** Поле «ресурс» і попередження після N виїздів; для ламп і дим-машин це реальніше за окупність.
