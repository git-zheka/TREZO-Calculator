# Деплой: від нуля до посилання

Усе на безкоштовних тарифах. Знадобиться акаунт GitHub — на нього чіпляються і Vercel, і Neon.

Орієнтовно 15 хвилин.

> Локально застосунок працює без бази, на `data/rider.json`. Для Vercel цього замало: там файлова система ефемерна, і записи зникають при холодному старті. Тому для онлайну — Postgres, і саме про це вся інструкція нижче. Змінна `STORAGE` на Vercel не потрібна: щойно з'явиться `DATABASE_URL`, застосунок сам піде в базу.

---

## 1. База — Neon

1. [neon.com](https://neon.com) → Sign up через GitHub.
2. Create project. Регіон бери найближчий — **AWS eu-central-1 (Frankfurt)**, звідти до Києва найменша затримка.
3. Після створення відкриється **Connection string**. Потрібен варіант із перемикачем **Pooled connection** — у ньому в хості є `-pooler`. Скопіюй увесь рядок, він виглядає так:

```
postgresql://neondb_owner:НАБІР_СИМВОЛІВ@ep-still-frog-12345678-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require
```

Безкоштовний тариф Neon: 0.5 ГБ і одна база. Для цього застосунку — тисячі замовлень, тобто десятиліття роботи.

> Neon присипляє базу після кількох хвилин без запитів. Перший запит після сну займає секунду-дві — це нормально й безкоштовно.

## 2. Код — GitHub

Якщо проєкт ще не в репозиторії:

```bash
git init
git add -A
git commit -m "Райдер на Next.js"
gh repo create rider --private --source=. --push    # або створи репо вручну на github.com
```

Репозиторій зроби **приватним**: там немає паролів (вони в env), але й показувати нічого.

---

## 3. Хостинг — Vercel

1. [vercel.com](https://vercel.com) → Sign up через GitHub.
2. **Add New → Project** → обери репозиторій `rider`.
3. Next.js визначиться сам, нічого налаштовувати не треба.
4. До натискання **Deploy** розкрий **Environment Variables** і додай три:

| Name | Value |
|---|---|
| `DATABASE_URL` | pooled-рядок із Neon (крок 1) |
| `APP_PASSWORD` | пароль, яким заходитимеш |
| `AUTH_SECRET` | `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |

5. **Deploy**. За хвилину буде посилання `rider-щось.vercel.app`.

Перший захід покаже помилку бази — таблиць ще немає. Це наступний крок.

---

## 4. Схема бази

З комп'ютера, один раз:

```bash
cp .env.example .env.local     # встав туди той самий DATABASE_URL
npm install
npm run db:push
```

Скрипт ідемпотентний: усі `create table if not exists`, тож ганяти можна скільки завгодно. Він же створює рядок налаштувань із секретом для календарного фіду.

Якщо локально вже щось наклацав у JSON-режимі — перенеси:

```bash
npm run db:migrate
```

Теж ідемпотентно (`on conflict do update`), тож повторний запуск не задвоїть записи. Курс переноситься, токен календаря — ні: на проді краще мати власний.

Онови сторінку на Vercel — має зʼявитись форма входу.

## 5. Іконка на телефоні

Chrome на Android: відкрий посилання → меню ⋮ → **Додати на головний екран**. Застосунок відкриється без адресного рядка, як звичайний застосунок. iOS: Safari → «Поділитись» → «На екран «Домів»».

Пароль запитається один раз — cookie живе пів року.

---

## 6. Календар у телефоні

У застосунку вкладка **Календар** → скопіюй посилання з панелі зверху. Виглядає як `https://твій-домен/api/ics/довгий-секрет`.

**Google Календар (з комп'ютера, у застосунку на телефоні цього пункту немає):**
[calendar.google.com](https://calendar.google.com) → зліва «Інші календарі» → **＋** → **Підписатись за URL** → встав посилання → «Додати календар».

Далі:
- Броні зʼявляться у застосунку Google Календаря на телефоні автоматично.
- Довгий тап на робочому столі → «Віджети» → Google Календар → «Розклад» або «Місяць».
- Google перечитує підписку сам, приблизно раз на кілька годин. Миттєвого оновлення не буде — це обмеження підписок на боці Google, не застосунку.

Посилання містить секрет: хто його має, той бачить твої дати. Якщо кудись засвітив — кнопка **«Оновити секрет»** у застосунку, стара підписка перестане працювати, і календар треба буде додати заново.

## Оновлення

`git push` у `main` — Vercel збирає й викочує сам. Змінні оточення міняються в Settings → Environment Variables, після чого потрібен **Redeploy**.

| | Безкоштовний ліміт | Скільки треба тобі |
|---|---|---|
| Vercel Hobby | 100 ГБ трафіку/міс, безлімітні деплої | десятки мегабайт |

## Якщо не піднімається

**«База не відповідає» після деплою** — не застосована схема (`npm run db:push`) або в `DATABASE_URL` не pooled-рядок. Перевір, що в хості є `-pooler`.

**Логін не пускає з правильним паролем** — `APP_PASSWORD` на Vercel зі зайвим пробілом або лапками. Значення вводиться без лапок.

**Постійно викидає на `/login`** — не заданий `AUTH_SECRET`, або він різний у Production і Preview. Cookie підписана одним, перевіряється іншим.

**Календар не тягне події** — відкрий посилання у браузері: має віддатись текст, що починається з `BEGIN:VCALENDAR`. Якщо 404 — секрет застарів після ротації.
